## Slide Copy

### 五個跨場共通問題

| 工程問題 | 需要固定的邊界 |
|---|---|
| 我是誰？ | identity、subject、owner、system boundary |
| 我能做什麼？ | scope、permission、tool、dependency |
| 目前狀態？ | session、transaction、resource、version |
| 怎麼證明？ | test、model、reconciliation、trace、claim |
| 失敗怎麼恢復？ | retry、rollback、fallback、human approval |

這五題不是把課程壓成同一套工具，而是用來檢查不同系統缺少哪一個可驗證邊界。

## Visualization Specification

- 主視覺為 Dark matrix；欄為 Architecture、Knowledge、Distributed、Agent、Operations，列為五個共通問題。
- Cell examples：Architecture 放 model／ADR／dependency；Knowledge 放 source／version／review；Distributed 放 transaction／reconciliation；Agent 放 scope／session／tool；Operations 放 alert／trace／recovery。
- Relations：每個課程對應多個 cell，但不填成熟度分數；以短名詞表示它提供的邊界或證據。
- Input：13 場課程的 notes、README 與可查 Artifact。Processing：抽取重複工程問題並保留各場語境。Output：跨場檢查框架，不是課程排名。
- 突出「證據」與「恢復」兩列，連接前面 S036、S039 的工程控制。

- 五列問題置左，五個工程領域置上；使用細線 grid，不做 dashboard 卡片堆疊。

## Evidence / Limitations

- 現場筆記與 Summary：13 場內容反覆出現邊界、狀態、驗證、可觀測性與恢復問題。
- 已存在 Artifact：Structurizr 的 DSL／ADR／workspace JSON 與 MCP Workshop `repo/` 是明確本地 Artifact；其他多數課程仍是 notes／README／圖片。
- 官方背景：各課程名稱與技術範圍來自對應 README；本頁不把官方介紹改寫成實作成果。
- 尚未確認：跨場矩陣不是正式研究分類，也沒有量化成熟度或總分。
