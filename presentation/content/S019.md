- Main Message: 當 Agent 代替組織購買安全情報，系統必須能說明誰授權、可花多少、向誰付款，以及結果如何追蹤。

## Slide Copy

### 一次付費查詢，至少要回答四個問題

- **誰在行動？** Security Agent 代表哪個組織或工作流程？
- **誰授權？** AP2 表達付款權限、預算與供應商限制
- **如何付款？** x402 將付款要求放回 HTTP 流程
- **如何協作與追蹤？** A2A 傳遞任務狀態；結果與授權決策留下紀錄

**重點不是讓 Agent 自己持有更大的權限，而是把代理行動拆成可驗證的責任。**

- System Boundary：Company / User Policy、Security Agent、Agent Runtime / Audit；External Dependencies：Security Intelligence Provider、Payment / Facilitator。
- Relations：Company / User Policy → AP2 authorization envelope → Security Agent；Security Agent → Provider request；Provider → HTTP 402；授權後的 payment signal → Provider / Facilitator → intelligence result；A2A 傳回任務狀態與結果 → calling workflow；所有關鍵決策 → Audit。
- Input：安全情報查詢、預算與供應商限制。Processing：確認身分、權限、費用與任務狀態。Output：可追蹤的付費結果，而非只有一個 API response。
