- Main Message: Observability 提供 Metrics、Traces、Logs 與事件，但 Root Cause 必須透過假設—證據—驗證的調查迴圈逐步收斂。

## Slide Copy

### Alert 之後，證據才開始集合

`Alert` → `Metrics` → `Traces` → `Logs` → `Config / Code Change` → `External Dependency` → `Hypothesis` → `Verification`

- 告警指出異常入口，不直接指出根因
- 不同資料源回答不同問題，需放回同一個時間與服務脈絡
- 證據不足時，回到下一個資料源，而不是直接下結論

## Visualization Specification

- 主視覺為深色 evidence sequence，右側約 58% 重繪人類工程師調查流程，左側約 42% 放裁切後照片。
- Nodes：Alert、Grafana、Metrics、Traces、Logs、AP Config、Code Change、External Dependency、Hypothesis、Narrow Scope、Verification。
- Relations：Alert → Grafana → Metrics → Traces → Logs；Logs → Hypothesis；Hypothesis → AP Config / Code Change / External Dependency；證據不足 → 回到 Grafana 或下一個資料源；足夠證據 → Verification。
- Input：告警與時間範圍。Processing：跨資料源查詢、建立假設、縮小問題範圍。Output：可被工程師檢查的調查結論，不是單一告警文字的推測。
- 突出回圈與「Observability ≠ Diagnosis」；不放入 SRE Agent 的自動化元件，留給 S026。
