## Slide Copy

### 兩種拓撲，保留同一個業務邊界

**Server 自己驗證**

`Client → MCP Server`：Server 讀 JWKS，驗 issuer／audience／expiry／scope，再執行工具。

**Kong 集中入口驗證**

`Client → Kong → MCP Backend`：Kong 驗 JWT 與入口條件；Backend 驗證可信任 Gateway 邊界，仍保留工具與資料權限。

撤銷後，離線 JWT 驗證可能繼續接受尚未過期的 Token。

## Visualization Specification

- 主視覺為 Before／After architecture split，左右各一個 System Boundary，中間以同一組業務權限標籤對照。
- Before Components：Client、MCP Server、JWKS／Issuer、MCP Tool。Data Flow：Client → Server → JWKS；Server → scope／audience check → Tool。
- After Components：Client、Kong Gateway、MCP Backend、MCP Tool、JWKS／Issuer。Data Flow：Client → Kong；Kong → JWKS／JWT validation → Backend；Backend → tool／data authorization。
- Trust Boundaries：Kong 是入口驗證層，Backend 是業務授權層；外部 Client 不可直接偽造 Gateway identity headers。
- Failure Path：Token 無效／audience 不符 → 401；scope 不足 → 403；Token 已撤銷但仍是離線有效 JWT → 可能暫時通過。Input 是 HTTP request 與 Token，Output 是拒絕、轉送或工具結果。
