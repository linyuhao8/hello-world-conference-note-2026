## Slide Metadata

- Slide ID: S022
- Section: Engineering Judgment
- Title: Design Review 也要保存被否決的方案
- Subtitle: 決策品質不只在最後選了什麼，也在於知道放棄了什麼
- Main Message: 讓 AI 提供替代方案後，Design Review 應保存選定方案、被否決方案與否決理由，才能累積可回顧的工程判斷。

## Slide Copy

### 一份決策記錄，至少保留四件事

1. **Chosen**：最後採用的方案與適用邊界
2. **Rejected**：曾經考慮但沒有採用的方案
3. **Why**：成本、風險、依賴或回復條件
4. **Consequence**：接受了什麼 trade-off，何時需要重新檢視

人先形成理解，AI 提供比較材料；Review 留下的不只是答案，還有取捨的脈絡。

## Visualization Specification

- 主視覺為可重繪的 Design Review record：中央為 Decision，左側為 Human Understanding，右側分岔為 Chosen / Rejected Alternatives，底部為 Reasons / Consequences。
- Nodes：Problem Context、Human First Design、AI Alternatives、Chosen Option、Rejected Option A/B、Decision Rationale、Trade-off、Review Trigger。
- Relations：Problem Context → Human First Design → AI Alternatives；Alternatives → Chosen Option / Rejected Option A/B；所有分支 → Decision Rationale → Trade-off；Trade-off → Review Trigger。
- Input：問題背景與初始設計。Processing：列出替代方案、比較限制、記錄否決理由。Output：可回顧的設計決策，而不是只留下最後一張架構圖。
- 主視覺要讓 Rejected 分支與 Chosen 分支同樣醒目；不新增未在資料中出現的具體架構元件。

## Layout Instructions

- 1920 × 1080、16:9；shadcn/ui-inspired，黑灰白，Technical / Minimal / Editorial。
- 使用非對稱版型：左側 28% 為問題與人理解，中間 44% 為 Chosen / Rejected 分岔，右側 28% 為理由與後果。
- Chosen 使用實線框，Rejected 使用虛線框；兩者皆保留，不用紅綠色做價值判斷。
- 文字只保留欄位標籤與短句，讓圖本身承擔主要敘事。

## Evidence / Limitations

- 現場筆記：人先設計、AI 提供替代方案與挑戰；設計評審應記錄被否決方案與原因；成長訊號包括能說明改善方向、設計理由與比較選項。
- 已存在 Artifact：Architecture Judgment 課程 README 與 notes；未找到正式 Design Review / ADR Artifact 可供展示。
- 官方背景：本頁是工程流程建議，不宣稱公司已有統一的 Review 模板或決策資料庫。
- 尚未驗證：被否決方案的保存格式、審查週期、責任人與回顧觸發條件。
