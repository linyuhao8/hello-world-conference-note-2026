# S005 — 速度、正確性與可恢復性必須一起量

## Slide Metadata

- **Slide ID：** S005
- **Section：** Engineering Takeaways
- **Title：** 速度、正確性與可恢復性必須一起量
- **Subtitle：** 一個候選方案，至少要回答「變快了嗎、仍然正確嗎、失敗後能處理嗎」
- **Main Message：** AI 提出的優化不能只用 TPS 或 latency 判斷；工程接受條件必須同時包含功能結果、資料一致性、運行特性與失敗後的診斷線索。

## Slide Copy

### 變更評估流程

`AI 提出候選方案`

→ `固定條件重跑`

→ `功能正確性`

→ `資料對帳`

→ `運行特性`

→ `Failure / Recovery`

→ `採用、退回或交人工`

### 四個檢查面

- **Function：** API 或流程得到預期結果。
- **Consistency：** ID、狀態、資產與跨服務數量可以對帳。
- **Runtime：** latency、throughput、backlog、error 與 cost 在相同負載下可接受。
- **Recovery：** 失敗時能重試、回滾、補償或留下足夠診斷證據。

### 工程結論

局部效能上升，只能證明候選方案值得繼續查，不足以直接證明它可以上線。

## Visualization Specification

- 以左到右的 verification pipeline 為主視覺，起點為 `Candidate change`，終點為 `Decision`。
- 每個 gate 顯示 Input／Check／Output：
  - **固定條件重跑：** 同版本、同負載、同測量窗口 → 可比較結果。
  - **功能正確性：** request／event → 預期結果或失敗案例。
  - **資料對帳：** 多服務 ID／狀態／數量 → reconciliation result。
  - **運行特性：** latency／throughput／backlog／error → runtime evidence。
  - **Failure / Recovery：** timeout／partial failure → retry、rollback 或人工決策。
