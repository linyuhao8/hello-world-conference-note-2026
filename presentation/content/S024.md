## Slide Copy

### 從個人習慣變成團隊 Gate

`個人工作流` → `Repository Convention` → `Automated Check` → `Review / CI Gate` → `Result Record`

- **共識文件**：Background、Goal、Non-goal、Acceptance Criteria
- **可執行規則**：Linter、Dependency Checker、Git Hook、CI
- **可追溯證據**：Atomic changes、Review decision、檢查結果

本頁的導入方向是建議，不代表現有團隊已完成整合。

## Visualization Specification

- 主視覺為由左至右的 asset map，不使用照片；三層責任以水平泳道表示。
- System Boundary：Repository / Team Workflow。Components：共識文件、Policy／Skill、Linter／Dependency Checker、Git Hook、CI、Reviewer、Result Record。External Dependency：Business requirement 與既有團隊規範。
- Relations：個人工作流產生文件與小變更 → Repository Convention 固化規則 → Local Check / Git Hook → CI Gate → Review／結果記錄；本機失敗可回饋到變更，CI 是第二次檢查。
- Input：需求與專案特殊規則。Processing：版本化、確定性檢查、人工 Review。Output：團隊共享的規則、證據與責任邊界。
- 突出「本機可能被繞過，CI 必須再次檢查」的雙層 Gate。

## Evidence / Limitations

- 現場筆記：專案規則留在專案內；跨團隊 Policy／Skill 可封裝成 Package／Library；先在單一專案驗證，再逐步推廣。
- 官方介紹：PRD、User Story、Design Document、Implementation Plan、Linter、Testing、Git Hooks 與 CI 是團隊化的候選資產。
- 已存在 Artifact：課程 README 與 notes；未找到公司級共用 Package、CI Gate 或 Result Store 的實作證據。
- 後續建議：從最近一次重複犯錯開始，將規則轉成可執行檢查；本頁不宣稱已導入。
