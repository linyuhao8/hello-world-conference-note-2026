## Slide Copy

### 同一個 Client，兩次授權，兩種結果

- `notes:read` + Resource A → `list_notes` 成功
- 同一個讀取 Token → `create_note` 回 `403 insufficient_scope`
- 重新取得 `notes:read notes:write` Token → `create_note` 成功
- Resource A 的 Token → Resource B 回 `401`

Server 依序驗證：`issuer`、簽章、`audience`、`expiry`、`access token type`，再檢查工具所需的 `scope`。

## Visualization Specification

- 主視覺使用實際 scope sequence 圖，佔畫面約 58%；右側補一條 Resource A／Resource B authorization boundary。
- Participants：Client、Signet Authorization Server、MCP Server A、MCP Server B。
- Message Direction：Client → Signet 取得 A 的 read Token；Client → Server A 呼叫 `list_notes` → `200`；Client → Server A 呼叫 `create_note` → `403 insufficient_scope`；重新授權取得 read/write Token → `200`；A Token → Server B → `401`。
- State Changes：匿名／未授權 → read scope → read + write scope；resource audience 從 A 到 B 不可沿用。
- Trust Boundaries：Signet 簽發 Token；Resource Server 驗證 Token 與工具權限；Client 不自行宣告權限。
- Error Path：scope 不足走 403；audience 或身份／Token 不適用走 401。Input 是 Token 與工具請求，Output 是工具結果或拒絕原因。
