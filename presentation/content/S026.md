## Slide Metadata

- Slide ID: S026
- Section: Incident Investigation
- Title: Webhook Receiver 與背景調查必須分離
- Subtitle: 快速回應事件，非同步執行長時間調查
- Main Message: Receiver 的責任是接收並快速回應；Background Worker 才負責工具呼叫、分析、保存與通知，兩者不能被同一個請求生命週期綁住。

## Slide Copy

### 入口要快，調查要可恢復

`Alerting System` → `Webhook Receiver` → `Background Worker` → `SRE Agent / Tools` → `Result Store + Notification`

- Receiver：驗證告警格式、建立任務、回 `200 OK`
- Worker：執行調查、取得資料、分析結果、保存與通知
- Queue、Retry、Timeout、Idempotency：是需要明確設計的失敗邊界，不是課堂已驗證的數字成果

## Visualization Specification

- 主視覺為 Technical flow + failure boundary，右側約 60% 重繪，左側約 40% 使用 Workshop photo-3 的架構局部。
- System Boundary：Incident Investigation Service。Components：Webhook Receiver、Queue / Task Boundary、Background Worker、SRE Agent、Tool Adapters、Result Store、Notification。External Dependencies：Grafana / Alerting System、Metrics／Traces／Logs／Kubernetes Events。
- Data Flow：Alerting System → Receiver；Receiver → `200 OK` 並寫入任務；任務 → Queue / Worker；Worker → Agent → Tool Adapters → observability sources；結果 → Result Store；異常或完成 → Notification。
- Input：HTTP Alert payload。Processing：非同步任務調查與多輪工具查詢。Output：結構化調查結果、保存紀錄與通知。
- 在 Receiver 與 Worker 之間畫粗邊界，旁邊標出 timeout／retry／idempotency 的待設計區域。
