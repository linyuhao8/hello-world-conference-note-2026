## Slide Copy

### 角色分工先於 Agent 數量

- **Researcher**：建立事實基礎，交付來源與未知項目
- **Builder**：依 contract 建立方案並使用工具
- **Reviewer**：檢查、測試、指出不符合處
- **Orchestrator**：決定 routing、順序與下一個責任人

Shared Context／Memory 保存交接所需狀態；每次交接都要有明確的 output contract。

## Visualization Specification

- 主視覺為 Technical orchestration diagram，中央 Orchestrator，左右分布 Researcher、Builder、Reviewer，底部為 Shared Context／Memory／Outputs。
- Components：Orchestrator、Researcher、Builder、Reviewer、Shared Context、Memory、Output Contract、Human Review。
- Relations：Orchestrator → Researcher（facts）；Orchestrator → Builder（solution task）；Builder → Reviewer（candidate + tests）；Reviewer → Orchestrator（findings / pass / retry）；各 Agent ↔ Shared Context / Memory。
- Input：任務與約束。Processing：routing、分工、工具執行、檢查與交接。Output：可被下一角色消費的結構化結果，或回到前一角色修正。
- Failure Path：缺少 output contract → 交接含糊；shared context 過大或錯誤 → 分工失真；Reviewer 失敗 → Orchestrator 重新 routing，而不是直接宣告完成。
