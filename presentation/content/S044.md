## Slide Copy

### 四個工程判準

1. **Boundary**：誰能做什麼，系統與權限邊界是否清楚
2. **State**：任務、交易、Token、版本與資源狀態是否可追蹤
3. **Evidence**：結果是否能透過測試、模型、claims、reconciliation 或 trace 驗證
4. **Recovery**：失敗是否能被發現、分類、停止、恢復或交給人工

速度是效率指標，不是正確性、授權或 Production readiness 的替代品。

## Visualization Specification

- 主視覺為 Minimal dark closing：中央四個同心但分離的判準節點，底部用一條細線連接 `Input → Execution → Evidence → Decision / Recovery`。
- Components：Boundary、State、Evidence、Recovery；外圍標示 Agent、Distributed System、Architecture Model、Operations 四類語境。
- Relations：Boundary 限制可執行範圍；State 保存過程；Evidence 支持判定；Recovery 處理失敗；四者共同形成可接受工程系統。
- Input：前 43 頁的案例、Artifacts、課程筆記與限制。Output：可重用的工程判準，不新增產品承諾或成熟度分數。
- Failure Path：缺 Boundary → 越權；缺 State → 無法追查；缺 Evidence → 無法判定；缺 Recovery → 失敗只能重跑或猜測。
