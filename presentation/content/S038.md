## Slide Copy

### 同一個依賴圖，兩種檢查視角

`Application → pagination → persistence`

- **Lint／depguard**：逐段檢查 direct import
- **Architecture Test**：從 Application 搜尋完整 dependency path
- **違規證據**：輸出完整路徑，而不是只有 `exit code != 0`

每一段看起來合法，組合後仍可能穿透架構邊界。完整路徑才是要阻擋的工程行為。

## Visualization Specification

- 主視覺為 dependency graph，左側呈現 direct edges，右側以高亮路徑呈現 Architecture Test 找到的違規。
- Nodes：Application、`pagination`、Domain、Persistence、Infrastructure；Relations：Application → pagination → persistence → Infrastructure，並畫出合法的 Application → Domain 路徑作對照。
- Direct edge view：每一段 import 各自標示 `allowed`。Full path view：從 Application 起點搜尋到 Infrastructure，將完整違規路徑以粗線標示。
- Input：package／module import graph。Processing：direct dependency rule 與 graph traversal。Output：通過、違規路徑與可供 Agent 修正的 failure message。
- Failure Path：空掃描、掃描範圍不完整或只看局部邊時，不得直接算成功；測試本身也要有合法與違規案例。
