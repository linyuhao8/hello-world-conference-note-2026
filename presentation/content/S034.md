## Slide Metadata

- Slide ID: S034
- Section: Harness Engineering
- Title: Prompt、Context、Harness 是三個不同控制面
- Subtitle: AI 不穩定時，先定位是哪一層出了問題
- Main Message: Prompt 控制 AI 怎麼說，Context 控制 AI 看得到什麼，Harness 控制 AI 能做什麼以及失敗後如何被觀測、驗證與恢復。

## Slide Copy

### 三層控制面對應三種工程責任

- **Prompt**：Input、Process、Constraints、Output Contract
- **Context**：RAG、MCP、Skills、Agents、Memory
- **Harness**：Orchestration、Evaluation、Observability、Recovery

同一個 Prompt 仍可能因 Tool timeout、Context 錯誤或缺少 trace 而產生不同結果。問題要回到對應控制面處理。

## Visualization Specification

- 主視覺為深色三層架構，右側約 58% 重繪，左側約 42% 放裁切照片作 Workshop evidence。
- Layers：Layer 1 Prompt、Layer 2 Context、Layer 3 Harness。
- Responsibilities：Prompt → structured input／process／output；Context → relevant knowledge／RAG／MCP／memory；Harness → tool access／orchestration／evaluation／observability／recovery。
- Data Flow：Input → Prompt constraints → Context assembly → Harness execution → Output；Failure signals 從 execution 回到對應控制面。
- Failure Path：Prompt 邊界模糊 → hallucination；Context 不完整 → 找錯資料；Tool timeout／無 trace → 無法診斷；Verification 失敗 → Recovery 或 Human Intervention。
