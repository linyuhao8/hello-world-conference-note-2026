- **Main Message：** C4 定義架構視角，Structurizr DSL 保存模型，Views 將同一份模型轉成不同溝通畫面，ADR 則保存選項、決策與後果。

## Slide Copy

### 四個角色

#### C4 Model

用 System Context、Container、Component、Code 逐層降低複雜度。

#### Structurizr DSL

保存人、系統、Container、關係與部署模型，成為可版本控制的 source。

#### Views

從同一份模型產生 System Context、Container、Component、Dynamic、Deployment 等溝通視角。

#### ADR

記錄 Context、Options、Decision、Consequences，回答「為什麼這樣設計」。

### 共同資料流

`需求與限制 → C4 Model → DSL source → Views / Validation → ADR context`

OpenCode 可以協助產生或修改模型，但架構邊界與取捨仍需要人確認。

## Visualization Specification

- 以水平 technical flow 為主視覺，五個階段由左至右：
  1. **Context：** 功能需求、非功能需求、既有系統、整合邊界。
  2. **C4 Model：** System Context → Container → Component → Code。
  3. **DSL Source：** `workspace.dsl` 保存元素、關係、部署與 view 定義。
  4. **Views：** System Context／Container／Component／Dynamic／Deployment。
  5. **ADR：** Context → Options → Decision → Consequences。
- 每個箭頭標註 Input／Output：Context 輸入限制；C4 輸出層級模型；DSL 輸出可版本控制 source；Views 輸出溝通視角；ADR 輸出決策脈絡。
- 在 `Views` 下方放一個小型 branch，標示「主管／工程師／維運／Agent」可以讀不同視角，但回到同一份模型。
- 在 `OpenCode` 旁放小型虛線註解 `協作工具，不是決策責任的替代者`。
- 不展示 Deployment View 的實際服務方塊；實際 Artifact 留給 S008。
