## Slide Copy

### 一個 Thread，是一個可持續的 Agent Session

`Discord／Slack thread` → `Gateway Adapter` → `Dispatcher／Session Pool` → `ACP stdio JSON-RPC` → `Agent Runtime`

- 同一 thread 延續 prompt、tool call、thinking、permission 與 streaming 狀態
- Session Pool 管理同時數量與閒置清理
- `Cancel／Resume` 與錯誤恢復屬於 Runtime lifecycle，不是單次 HTTP request

## Visualization Specification

- 主視覺為深色 sequence + lifecycle state diagram，全部使用 CSS／SVG 重繪，無課程圖片。
- Participants：Discord／Slack User、Gateway Adapter、Dispatcher、Session Pool、ACP Client、Agent Runtime。
- Message Direction：User 在允許頻道 mention → Adapter 建立或取得 thread session；Dispatcher → Session Pool；ACP Client ↔ Agent Runtime 傳送 JSON-RPC prompt、tool call、thinking、permission、streaming event。
- State Changes：`new` → `running` → `streaming` → `waiting permission`／`cancelled` → `completed` 或 `resumable`；閒置超過 TTL → `expired`。
- Trust Boundaries：聊天平台身份與頻道權限在 Adapter；Agent tool permission 在 ACP／Runtime；Session Pool 不應把平台 allowlist 當作 Agent 權限。
- Input：thread message。Processing：session lookup、runtime message routing、streaming。Output：持續更新的回覆、工具事件與可取消的工作狀態。

## Evidence / Limitations

- 現場筆記：OpenAB 以 thread 對應 agent session，經 dispatcher／session pool 透過 ACP stdio JSON-RPC 連接不同 Agent Runtime；notes 提到預設 TTL 24 小時與 max_sessions 10。
- 官方背景：ACP 提供 Client 與 Agent 間的共通介面，OpenAB 支援多種 coding agent backend。
- 已存在 Artifact：本 Repository 只有課程 README 與 notes，沒有 OpenAB 原始碼或本地 Runtime Artifact。
- 尚未確認：本環境是否實際部署 OpenAB、特定 Agent 版本輸出、cancel／resume 的完整行為與 session persistence。
