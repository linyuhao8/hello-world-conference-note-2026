## Slide Copy

### 證據形式跟著系統責任改變

| 系統案例 | 主要邊界 | 可檢查證據 | 不能直接推論 |
|---|---|---|---|
| Structurizr | model／decision | DSL、ADR、workspace JSON、validation | AWS Production 已部署 |
| Event-driven Trading | correctness／consistency | transaction、lock order、reconciliation、benchmark 条件 | Production Capacity |
| MCP OAuth2 | identity／authorization | token claims、scope、audience、401／403、validation | 企業 IAM 完整驗收 |
| Harness／Agent | execution／recovery | session、trace、span、metric、log、verification | Runtime 已在本 Repository 完成 |
| Architecture Test | dependency boundary | direct edge、完整 path、failure reason | 所有架構規則已自動化 |

## Visualization Specification

- 主視覺為 Light comparison table，五列案例、四欄比較維度；不計算分數、不使用排名色彩。
- Comparison Dimensions：系統責任、證據形式、可驗證結果、限制／不可推論。
- Evidence：Structurizr 使用 DSL／ADR／JSON；Trading 使用一致性與負載條件；MCP 使用 claims 與 HTTP status；Harness 使用 runtime events；Architecture Test 使用 dependency path。
- Trade-offs：模型可重現不等於部署；吞吐提升不等於 correctness；Token 有效不等於工具授權；有 trace 不等於 recovery 已完成；Lint 通過不等於完整路徑合法。
- Input：前 40 頁的課程案例與 Artifact。Output：依問題選擇證據的比較方式，而非跨系統總分。
