## Slide Copy

### 三個角色，三段責任

- **Client**：引導登入、保存 Token、發出 MCP 工具呼叫
- **Authorization Server（Signet）**：登入與同意、簽發 Access Token
- **Resource Server（MCP Server）**：驗證 issuer、audience、expiry、scope，決定工具是否放行

Kong 在 Lab 06 可集中入口驗證；MCP Backend 仍保留工具與資料權限。

## Visualization Specification

- 主視覺為深色 three-column sequence，不使用任何真實 Token 或帳號截圖。
- System Boundary：MCP OAuth2 Workshop。Components：MCP Client／CLI、Signet Authorization Server、Kong Gateway（Lab 06）、MCP Server／Backend、MCP Tool。
- External Dependencies：瀏覽器登入、JWKS metadata、Signet issuer。
- Data Flow：Client → Signet：登入／同意／PKCE；Signet → Client：Access Token；Client → MCP Server 或 Kong：帶 Token 的工具請求；Server / Kong → JWKS：驗證簽章；Kong → MCP Backend：可信任入口；Backend → MCP Tool：scope 與資料權限檢查。
- Input：使用者授權與工具請求。Processing：Token 驗證、scope／audience 判斷。Output：工具成功、401 或 403。
