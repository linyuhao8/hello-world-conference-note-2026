# S004 — AI 品質不是 Prompt 單點問題

## Slide Metadata

- **Title：** AI 品質不是 Prompt 單點問題
- **Subtitle：** Prompt、Context 與 Harness 分別控制不同的工程責任
- **Main Message：** Prompt 決定任務如何被描述，Context 決定 Agent 看得到什麼，Harness 則負責工具、狀態、觀測、驗證與恢復。

## Slide Copy

### 三層工程模型

#### Prompt

定義任務、輸入、限制與輸出格式。

**控制：** AI 怎麼說。

#### Context

提供 RAG、MCP、Skills、Agents、Memory 等任務所需資訊。

**控制：** AI 看得到什麼。

#### Harness

管理 Tool、Orchestration、State、Observability、Verification 與 Recovery。

**控制：** AI 能做什麼，以及做錯了怎麼處理。

### 工程判準

同一個 Prompt 即使拿到正確 Context，也不代表 Tool 一定成功、結果一定可驗證，或失敗時一定能恢復。

## Visualization Specification

- 使用三層由下至上的架構圖：`Prompt → Context → Harness`。
- 每層左側放「輸入問題」，右側放「控制的工程面」：
  - Prompt：任務／限制／Output Contract
  - Context：文件／工具描述／記憶／當下狀態
  - Harness：Orchestration／Tool Permission／Trace／Verify／Recover
- 從底部畫一條執行流：`Task → Agent execution → Tool call → Evidence → Decision`。
- 在 `Evidence` 後分成 `Pass → continue` 與 `Fail → retry / fallback / human`，突出 Harness 的控制責任。
- 不把 Prompt、Context、Harness 畫成 UI 卡片；使用層級、連線與責任標籤表達關係。
