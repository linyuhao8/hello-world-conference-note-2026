## Slide Copy

### 同一筆交易，四個不同責任

- **A2A｜任務協作**：把工作交給另一個 Agent，處理狀態與長任務交接
- **x402｜付款觸發**：服務回 `HTTP 402`，Agent 簽署付款後重送請求
- **AP2｜授權與預算**：限制誰可付、可向誰付、單次與每日預算
- **Ghost Pay｜基礎設施隔離**：由 sidecar / proxy / Paymaster 處理付款，不讓業務 Agent 持有私鑰

## Visualization Specification

- 主視覺為「HTTP 交易主流程 + 四層責任標註」，左側 45% 使用 x402 Workshop 圖片裁切，右側 55% 重繪。
- Nodes：Business Agent、A2A Task Handoff、Provider、HTTP 402、AP2 Policy、Ghost Pay Sidecar / Paymaster、Facilitator、HTTP 200 Result。
- Relations：Business Agent → Provider；Provider → HTTP 402；AP2 Policy 檢查授權與預算；Ghost Pay Sidecar / Paymaster → Facilitator → payment proof；proof → Provider；Provider → HTTP 200 Result；長任務狀態透過 A2A 回到 calling Agent。
- Input：業務任務與付款政策。Processing：任務協作、付款挑戰、授權檢查、金鑰隔離。Output：服務結果與可追蹤的付款紀錄。
- 用四條對齊標籤線標明各自責任；不要把 A2A 畫成付款協議，也不要把 AP2 畫成支付執行器。
