## Slide Copy

### 一個入口，三層執行，有限回復

`Agent → make verify → 通過 → Git Hook → CI／Branch Protection`

若失敗：

- 保留 `stdout`、`stderr`、lint message、violation path、failure reason
- 在 retry budget 內回饋 Agent 修正
- retry 用盡，停止自動修正並交由人工判斷

本頁描述可導入的防線，不宣稱本 Repository 已完成同一套 CI 設定。

## Visualization Specification

- 主視覺為 Light enforcement pipeline，中央是一個共用的 `make verify` command，向三個執行邊界分支。
- Nodes：Agent、`make verify`、Git Hook、CI、Required Check、Branch Protection、Human Review、Evidence Store。
- Relations：Agent → `make verify`；通過 → Git Hook／commit／push；CI → Required Check → Branch Protection → merge；失敗 → Evidence Store → Agent retry；retry budget exhausted → Human Review。
- Input：變更集與規則。Processing：lint、test、architecture check、錯誤收集與有限重試。Output：可合併變更、可修正 feedback 或人工接管。
- Failure Path：Hook 可被 `--no-verify` 繞過時，CI／branch protection 必須成為最後門檻；skipped 或 neutral 不得被視為成功。
