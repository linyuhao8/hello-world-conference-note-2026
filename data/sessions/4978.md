光靠 Prompt 守不住架構：用 Lint 與 Architecture Test 打造 Agentic Coding 防護牆
寫下規則很容易，讓 Agent 每次都遵守卻很難。
許多團隊會把架構規範寫進 AGENTS.md、CLAUDE.md 或 .github/copilot-instructions.md：domain 不得依賴 infrastructure、frontend component 不得直接呼叫 API client、不同 feature 不得任意跨界。
即使這些規範已經進入 Context，它們仍然只是 soft constraints，無法保證 Coding Agent 在每一輪修改中都穩定遵守。
任務越長，架構越容易被最短路徑侵蝕。
當修正迴圈增加，Agent 經常會優先選擇最快讓程式通過的方法，原本清楚的架構邊界，也可能在一次次修改中逐漸失守。
因此我們需要把架構意圖變成可執行的防護牆。
這場演講將示範如何在後端透過 golangci-lint、depguard 與 Go Architecture Test 驗證 package dependency；在前端則使用 dependency-cruiser，限制跨 layer、跨 feature，以及 component 直接依賴 API client 等違規關係。
重點不是重新打造工具，而是組合既有工具形成多層防線。
從通用靜態規則到具有專案語意的架構驗證，讓規範不只存在於 Prompt 與文件裡，而是成為 Coding Agent 每一次修改都必須通過的工程條件。
聽眾收穫：
理解為什麼 AGENTS.md、Prompt 與文件規範不足以保證 Coding Agent 遵守架構邊界，以及如何將 soft constraints 轉換為 executable guardrails。
掌握 Lint、Dependency Analysis 與 Architecture Test 在架構治理中的角色差異，建立從通用規則到專案特定驗證的多層防護策略。
學習如何在 Go 與 Frontend 專案中實作架構約束，例如 package dependency、layer boundary、feature isolation 與 component 使用規範。
了解如何設計能被 Coding Agent 理解的驗證回饋，讓 failing test 成為 Agent 自我修正流程的一部分。
建立一套面對 Agentic Coding 時的工程治理思維：將架構意圖從「需要被記住的規則」轉變為「每次修改都必須通過的驗證條件」。
