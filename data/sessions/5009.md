從 Hello World 看懂 AI 開發工具的計費結構——如何省得到錢
當 AI 開發工具從「固定次數」改為「用量計費」，開發者第一次需要理解：我送出去的那句話，究竟被算了什麼錢？
這場議程從一個實驗開始：在 VS Code 送出同一句 Hello World，第一次花掉 6.64 個計價單位，第二次卻不到 1。拆開來看，你打的字其實只佔一小部分——真正的成本來自工具在背後組出的那份長請求：常駐指令檔、工具與 MCP schema、對話歷史。而前面沒變的部分可以走快取重用，一旦前綴變了就得整段重算，照原價收費。
弄懂這個結構之後，省錢的優先順序就清楚了：先控 output、再瘦身結構性 input、最後養成快取友善的操作習慣。我會實機示範幾個最常打斷快取的日常動作——讓計價數字自己說話，並補上台灣開發者容易忽略的相關案例。
內容以 GitHub Copilot 與 VS Code 實作，機制本身跨工具通用。帶走一份個人與團隊都能當天套用的檢查清單。
適合已在日常使用 AI 開發工具、想弄懂帳單為何居高不下的開發者與 Team Lead。
聽眾收穫：
• 能拆解一次 AI 編碼互動的成本組成
• 知道省錢的正確優先順序
• 能在當天完成三項具體調整
• 能判斷哪些日常操作正在花冤枉錢
• 具備跨工具遷移的判斷力
