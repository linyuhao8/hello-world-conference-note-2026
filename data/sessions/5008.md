## Official Description

2026-10-15 13:30 - 14:00 A 會議室
SHARE
初級工程師如何 AI 賦能的翻寫一個跟自己年紀差不多大的框架
SDLC 過去最常被犧牲的環節，像是沒時間寫測試、排不出重構，在 AI 時代反而更該重視。這場演講分享我在真實商業專案（legacy 系統現代化）中每天運轉的工作流。從 pm skill 負責釐清需求背後的「為什麼」，產出 User Journey 與驗收標準；arch skill 盤點專案慣例與可重用內容，產出架構文件；Implementer subagent 帶著開發哲學的 system prompt 實作（「先讓改動變容易，再做那個容易的改動」）；Test-reviewer 專門審查測試是否真的產生 confidence、有沒有偷改測試掩蓋 bug；Reviewer 用工程判準抓過度嵌套、競態條件與被繞過的 invariant；最後 QA 以 fork context 驗收，不過就退回修正，直到 pass。
聽眾收穫：
1. 一套可直接複製的 subagent pipeline 設計:PM → 架構 → 實作 → 測試審查 → 程式審查 → QA 的角色拆分與銜接文件
2. 各角色 system prompt 的設計原則:如何把工程哲學與判準寫進 prompt,而不是每次重講
3. AI 時代的 SDLC
4. 單人開發者也能維持團隊級的品質防線
Maple Kuo
