## Official Description

2026-10-14 15:30 - 17:30 603+604 會議室
SHARE
把「做完了」寫下來：90 分鐘做出一份機器能檢查的驗收清單
15:30–16:00｜環境準備時間
可提早入場準備。
15:55｜正取入場截止／開放備取入場
正取人員請於 15:55 前入場完畢；逾時未入場之名額將釋出，並依備取順序開放入場。
16:00–17:30｜工作坊時段
這是一場 SDD（Spec-Driven Development）＋ Harness 的實作工作坊。90 分鐘，你會用 AI coding agent（不限品牌，Claude Code、Codex CLI 等皆可）跑一輪完整的開發流程：寫 spec、讓 agent 實作、驗收、修正。
流程：
1. 我先示範一次完整的 SDD + Harness 循環，從 spec 到 agent 產出到驗收。
2. 你自己動手跑一輪：寫 spec、讓 AI agent 實作，agent 回報「做完了」。
3. 針對這次產出寫 2–5 條驗收條件，每條標明「證據在哪」——這是你的第一份驗收清單。
4. 把其中至少一條變成一支能跑的 eval。不是所有條件都能用一支 script 解決：有些能直接寫成腳本驗、有些要靠另一個沒看過你怎麼做的 agent 幫你抓、有些只能人工判斷——我會示範這三種各一次。
5. 我會現場抽幾份清單，問「這條的證據在哪一行」，帶大家看哪些條件其實驗不到、要換方法。
需要準備：至少一種可用的 AI coding agent（不限品牌，能執行 agentic coding 即可）與對應訂閱方案、一台能跑終端機的筆電。歡迎自備一個想驗證的小任務或 spec，沒準備的話我會提供固定範例。
課程目標
一次完整跑過的 SDD + Harness 循環——不是投影片上的流程圖，是自己動手跑過一次。
至少 2 份自己領域的驗收清單草稿，每條都寫著「證據在哪」。
一支或多支可重複使用的 eval，依驗收條件類型而定（腳本驗／交叉 agent 驗／人工判斷）。
一份「哪種驗收條件該用哪種驗證方法」的判斷依據——這是這場工作坊真正想留下的東西，比任何一支 script 都值錢。
學員自備裝置
一台能跑終端機的筆電（Windows 建議搭配 WSL 或 Git Bash），並請於現場前準備好至少一種可用的 AI coding agent（不限品牌，Claude Code、Codex CLI 或其他同類工具皆可）與對應訂閱方案
學員基礎能力需求
具備基本 CLI／shell 操作經驗即可，不需要特定語言或框架背景
課前準備
請準備好一種可用的 AI coding agent 帳號（不限品牌，已訂閱對應方案即可）；歡迎自備一個想驗證的小任務或 spec，沒準備的話現場會提供固定範例
