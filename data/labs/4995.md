Google AI Studio X Antigravity 驗收實戰
10:10–10:40｜環境準備時間
可提早入場準備。
10:35｜正取入場截止／開放備取入場
正取人員請於 10:35 前入場完畢；逾時未入場之名額將釋出，並依備取順序開放入場。
10:40–12:10｜工作坊時段
「Vibe Coding」講了一兩年，大家都會了：你用自然語言請 AI 幫你寫，它很快給你一個能跑的東西。Agent-first 又更進一步：你給高階目標，Agent 自己規劃、實作、測試、驗證，最後跟你說「做完了」。
問題就在這句「做完了」。
我開一間軟體公司，在彰化與全台灣替在地團隊、企業和政府機關做了很多案子。這一年我把公司的出貨流程整個押在 AI 協作上，人只在關鍵節點把關（所謂的 Human in the loop）——Agent 出包，是我賠錢、責任我扛。押下去之後我最深的體會是：Agent 時代最稀缺的能力不是「做出來」，而是「看出來」——它說它做完了，它到底做對了沒有？你敢不敢把這個東西交給付錢的客戶？
做出來現在很簡單，幾乎人人都做得到。真正會賠錢的，是那種「看起來很漂亮、跑起來也沒事，但你不敢出貨」的產出——而這種東西，Agent 現在很會生。
這場工作坊，你會做出東西，但那不是終點，是教材。90 分鐘裡你練三件事：
一、把含糊的需求變成規格。開場我給你一份真實的在地客戶需求書（已匿名）——含糊、自相矛盾、預算卡死、客戶自己都還沒想清楚。這不是 Todo App 的規格，這是真實世界的真實需求。你要用 Google AI Studio 把它變成一個能跑的原型。
二、驗收 Agent 的產出。原型帶進 Antigravity，你給 Agent 高階目標、review 它的實作計畫、看它自己用瀏覽器驗證 UI。然後是重頭戲：我發給你一份「Agent 說它做完了」的產出，它看起來很漂亮，但是裡面埋了 3 個坑——全都是我真的踩過、而且差點就出貨的那種。你的任務不是寫，是抓。
三、決定敢不敢出貨。最後用真實約束檢查它：一位六十歲的在地店家老闆，用他那支舊手機開得起來嗎？這東西一個月要燒多少錢？客戶禮拜五下午五點改需求，它改得動嗎？然後你做那個技術長真正在做的決定——收貨，還是退回。
全程在瀏覽器完成：AI Studio 開網頁就能用；Antigravity 我們用它的 CLI（agy）跑在 Google Cloud Shell，不用裝任何東西，不分 Windows / Mac 平台。
這不是「Antigravity 入門導覽」。工具會換，一年後可能換成別的 Coding Agent——但「怎麼驗收一個 Agent 說它做完的東西」不會過期。你帶走的是這個。
開場：Agent 時代最稀缺的是「看出來」
摘要：工作坊框架與任務說明──發放匿名化的真實客戶需求書（作為全程實作素材，不做案例背景或專案介紹）
第一節：把含糊需求變成規格
摘要：學員動手解讀需求書──圈出可實作的規格、標記含糊與矛盾處，快速分享；講師示範從規格到原型的最短路徑
類型：學員實作＋操作示範
第二節：AI Studio 原型實作
摘要：學員用 Google AI Studio 將需求書轉成能跑的網頁原型（瀏覽器開啟即可使用，無需安裝）
類型：學員實作
第三節：指揮與審查 Agent
摘要：講師示範在 Cloud Shell 以 agy 下高階目標；學員對自己的原型實際操作──下目標、review Agent 的實作計畫與自我驗證結果
類型：操作示範＋學員實作
第四節（本工作坊的核心）：抓出 3 個坑
摘要：發放一份「Agent 說它做完了」的完成品（內埋 3 個講師真實踩過的坑）；學員動手驗收、找出「看起來像對的錯」，可兩人一組或有獎徵答，逐一揭雷討論
類型：學員實作＋討論
第五節：收貨，還是退回?
摘要：學員以真實約束檢核表（裝置相容、月成本、可改動性）對產出做出貨判斷,全場表決與交流
類型：學員實作＋討論
結語：帶走的東西
摘要：發放出貨前檢查清單、GitHub 範本與步驟小抄；Q&A
課程目標
● 一套驗收 Agent 產出的方法：從含糊 brief 到規格、從「跑起來」到「敢出貨」
● 親手跑完一條 Agent-first 開發流（AI Studio 原型 → Antigravity 規劃／實作／自我驗證），全程瀏覽器、零安裝
● 對 Agent 常見誤區的實戰直覺：哪些錯看起來像對的
● 一份可帶走的出貨前檢查清單，以及 GitHub 範本與步驟小抄，回去就能套用在自己的專案
