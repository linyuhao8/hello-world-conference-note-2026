PART 3 / ENGINEERING PRACTICES

Structurizr 帶入系統分析與開發流程

從需求脈絡逐層建立可維護的 Architecture as Code

01 / CONTEXT

業務需求與情境

先釐清使用者、系統目標與外部依賴。

02 / SYSTEM

系統邊界

界定哪些責任屬於本系統，哪些由外部服務提供。

03 / CONTAINER

應用程式與服務

整理主要服務、資料庫與服務間的關係。

04 / COMPONENT

元件職責

需要深入時，再拆解服務內部的責任與資料流。

05 / DECISIONS

部署與 ADR

用 Deployment View 和 ADR 保留部署關係與方案取捨。
