PART 2 / COURSE REVIEW · 10/14 13:30–14:00 · 蔡宜庭 ET

用 AI 工作流重整事件驅動交易系統

一致性、效能與監測

講師：蔡宜庭（ET）
講師經驗：國泰金控 Java 後端工程師，專注事件驅動架構、可觀測性與可靠訊息處理，也使用自動化測試、分散式追蹤與可重現 Benchmark 驗證 AI 產出。
系統：Order · Wallet · MatchEngine · RabbitMQ · PostgreSQL · Redis Lua　 測試：k6
01 / INPUT

現有交易系統

買賣雙方下單；Order 記錄、Wallet 保留資產、MatchEngine 撮合並產生事件。

02 / OBSERVE

觀測瓶頸與證據

查看 DB 寫入、延遲、Queue backlog、錯誤與三服務成交資料對帳。

03 / CHANGE

AI 協助修改

依瓶頸提出批次清理、排程隔離或資料關聯修正。

04 / RE-RUN

同條件實測

重新壓測，並檢查吞吐、積壓、延遲、交易 ID 與資產是否一致。

05 / OUTPUT

採用或拒絕

速度改善且資料正確才採用；出現部分提交或對帳錯誤就退回修正。

Input現有架構、負載條件、遙測資料與正確性檢查
Output可重跑的修改方案、實測結果與採用決策
